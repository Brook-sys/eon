# ADR-0012: Operador zero-obrigatório; PendingDemands; CLI primeiro

- **Status**: aceito (2026-10-13)
- **Origem**: D14, D15 — docs/plan/00-DECISIONS.md

## Contexto

A invariante 8: o humano é onipotente e nunca obrigatório. A v1 parava esperando resposta. Pergunta que bloqueia é desenho errado — o autômato tem que ter sempre trabalho legítimo para fazer enquanto espera.

## Decisão

Perguntas ao humano = **PendingDemand**: não-bloqueante, com TTL, escopo local. O autômato continua iterando em outras frentes enquanto espera; planeja para não acumular perguntas (empacota decisões pendentes por tema em vez de ping-pong). Humano visualiza tudo em tempo real e interfere quando quiser — nunca precisa (invariante 8). Interfaces: **CLI primeiro** — log estruturado + `eonctl` desde o M1; dashboard web (timeline SSE, diffs, orçamento) no M2, desenhado já no blueprint.

## Consequências

- Nenhuma fila do sistema tem o humano como único consumidor.
- O dashboard é observação, não controle obrigatório; a CLI cobre 100% da operação.
- Demandas expiradas viram Lesson ("decidi sozinho por causa X") — o protocolo de autonomia é auditável.
