# ADR-0009: Lessons mecânicas — SOFT→HARD por corroboração

- **Status**: aceito (2026-10-13)
- **Origem**: D24 — docs/plan/00-DECISIONS.md (fecha A01)

## Contexto

Modelos fracos geram fracasso ruidoso: um erro pode ser azar, não lei. Cegar uma frente por um único fracasso é tirania de outlier; nunca cegar é ignorar padrão. A v1 acumulava "lessons" narrativas que ninguém aplicava.

## Decisão

Lesson = **regra mecânica**, 3 tipos nucleares (mínimo extensível; novos tipos só por ADR): `DEMOTE` (rebaixa prioridade de candidatos de uma classe), `BLOCK` (elimina classe de candidatos), `CONSTRAINT` (restringe parâmetros, ex.: `max_tokens ≥ 1024` para um perfil). **Autoridade graduada por corroboração**: 1ª Lesson de uma classe → regra SOFT (só demotion); 2ª Lesson independente da mesma classe → promove a HARD BLOCK. Um único fracasso nunca cega uma frente; dois independentes sim — sem humano necessário. **Expiração**: toda regra tem `review_after` + decaimento de peso; candidato pode atravessar um BLOCK declarando explicitamente "por que desta vez é diferente" — se falhar de novo, a regra sai reforçada.

## Consequências

- A memória de fracasso vira máquina: barata de aplicar, cara de ignorar, sempre reversível.
- Erro transiente de provider nunca vira Lesson (interage com D29: classes de erro separadas de Lessons).
- F3 e F2 leem as regras ativas como dados; a política de expiração é ela mesma Improvement (D35).
