# ADR-0006: Modelo OpenAI-compatible único; piso 7B; calibração e perfis de dialeto

- **Status**: aceito (2026-10-13)
- **Origem**: D05, D27, D29 — docs/plan/00-DECISIONS.md

## Contexto

Provedores heterogêneos (Ollama local, Groq, NIM, OpenRouter, LM Studio), cotas gratuitas, dialetos de erro divergentes (herança empírica da v1: Groq 429/Retry-After). Design tem que sobreviver ao modelo mais fraco disponível.

## Decisão

Um contrato só: OpenAI-compatible `/v1/chat/completions`, um adapter com perfis de dialeto recalibráveis. Piso de design: modelos 7B de instrução-fraca; sem dependência de tool calling nativo ou JSON mode obrigatório. Calibração (D27): ~12–15 probes baratas em 4 famílias (formato, instrução exata, coerência multi-passo, janela útil); nível atribuído por MÍNIMO (fail-safe); recalibração em boot + troca de binding + anomalia + semanal com cap. Erros de provider (D29): tabela de classes — 429/Retry-After espera exata; 5xx backoff exponencial com jitter; 4xx de payload 1 reparo determinístico; parse failure ladder de reparo; cota esgotada → THROTTLED + Ciclo 2 acelera; circuit breaker 5 falhas → degrada a L0, half-open com probe barata.

## Consequências

- Trocar provedor é trocar perfil, não código; erro transiente nunca vira Lesson espúria.
- Ordem do M2 é encadeada (D46): adapter → calibração → missão F1.
- Perfis empíricos da v1 (Groq/NVIDIA) são insumo documental, não código herdado.
