# ADR-0003: SQLite híbrido — tabelas por agregado + events append-only + outbox

- **Status**: aceito (2026-10-13)
- **Origem**: D03, D30, D31, D44 — docs/plan/00-DECISIONS.md

## Contexto

A v1 usava blob-checkpoint (o pecado canônico): estado opaco, irconsultável, irreproduzível. Falha de storage precisa de protocolo, não de esperança.

## Decisão

SQLite real (puro-Go): tabelas canônicas por agregado + `events` append-only + `outbox`. Nada de blob-checkpoint. WAL; transação por ChangeSet; migrações versionadas embutidas testadas em cadeia. Índices canônicos por agregado + cursor pagination (sem OFFSET); FTS5 para memory (D44). Compactação por idade+uso como changeset auditável, executor F2-higiene (D30). Falha fatal de storage (D31): incidente registrado → storage novo → re-bootstrap do essencial → F2 re-importa a essência de export markdown versionado no git (delta incremental por janela do Ciclo 2) → modo degradado, nunca parado.

## Consequências

- Estado consultável por SQL, rastreável por replay; export de essência limita perda a ~1 janela de reflexão.
- Contratos de storage estreitos por repositório (anti-god-interface da v1).
- Detalhe de schema é tarefa do M1 (docs/plan/05); este ADR fixa a FORMA, não as tabelas.
