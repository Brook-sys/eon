# ADR-0007: Loop multiciclo serial C0–C4; sleep-time compute

- **Status**: aceito (2026-10-13)
- **Origem**: D10, D12, D22, D28 — docs/plan/00-DECISIONS.md

## Contexto

O loop linear da v1 não tinha lugar para reflexão, evolução nem vida — tudo competia pelo mesmo passo. Free-tier exige que NUNCA haja mais de uma chamada de modelo em voo (custo + consistência: τ-bench pass^8 < 25% mesmo para modelos fortes) e que a fila vazia não seja término.

## Decisão

Loop multiciclo C0–C4 (D22): **passo** (microturn + verificação por passo) / **tarefa** (decomposição + Lesson) / **reflexão** (memória, sleep-time compute) / **evolução** (F3, recalibração) / **vida** (frontier, missão). Serialidade cognitiva estrita (D10): uma chamada de modelo em voo, sempre; paralelismo só em capabilities determinísticas com teto explícito. Orçamento é entrada de scheduling (D12): cota esgotada → F2 determinística e F3-sandbox continuam (sleep-time compute); loop nunca dorme. Gatilhos do Ciclo 2 (D28): híbrido rotina (N≈10 tarefas + idade de memória) + acelerador (cota esgotada/idle).

## Consequências

- O kernel é determinístico e auditável; sem leases, sem corrida por cota.
- Degradar com elegância substitui parar: cada estado de recurso tem trabalho legítimo definido.
