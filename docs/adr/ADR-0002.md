# ADR-0002: Módulos compile-time; fronteiras por checker AST; teto de diff

- **Status**: aceito (2026-10-13)
- **Origem**: D02, D32, D45 — docs/plan/00-DECISIONS.md

## Contexto

A v1 morreu de god packages e fronteiras imaginárias: nada impedia `internal/kernel` importar tudo. Plugins runtime (WASM/hashicorp) e frentes como processos separados foram rejeitados por custo/complexidade.

## Decisão

Modularidade = módulos em TEMPO DE COMPILAÇÃO com interfaces estreitas. As fronteiras são ENFORÇADAS por checker próprio (`tools/boundary`, Go+AST): `go/parser` lê `rules.json` declarativo (allowlist de import por pacote, orçamento de linhas por pacote, teto de linhas por arquivo, banimento de dependência externa não registrada). Pacote interno não registrado = violação. Checker roda no CI, na skill `eon-verify` e é testado com violação proposital (que reprova). Commits conventional com teto de diff: >500 linhas em PR reprova (D45). A única exceção-leaf documentada: `internal/statefile` (util de filesystem com semântica de stdlib estendida) pode ser importado por core/supervisor/worker.

## Consequências

- Fronteira que não está no rules.json não existe; violação é erro de CI, não opinião de revisão.
- Dependência externa é ADR, nunca acidente (D19 no espírito, aplicado a deps).
- A raiz de composição (`cmd/eon`) é o único lugar que importa tudo — inclusive a detecção de sandbox no boot, injetada via config/env nos outros processos.
