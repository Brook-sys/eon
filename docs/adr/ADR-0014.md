# ADR-0014: Deploy e continuidade via Portainer; watchdog sidecar

- **Status**: aceito (2026-10-13)
- **Origem**: D08, D40, D47, D49, D50, D51, D52, D53, D54, D55 — docs/plan/00-DECISIONS.md

## Contexto

O deploy tem que ser operável por um humano com bare-minimum de esforço e verificável de fora (o autômato não pode verificar a si mesmo subindo). Portainer já existe no homelab com o stack `eon` (id 52, ambiente `local` id 3) da era v1. A camada-casca é imutável para o autômato — então a plataforma que a move também é.

## Decisão

- **Plataforma (D49)**: Portainer é a plataforma de deploy E dos testes de continuidade. Stack `eon` reaproveitado: compose reescrito para a casca v2 (`deploy/stack-eon.compose.yml`), mantendo nome, volume `eon-data` e identidade. O autômato **nunca** recebe credenciais Portainer nem `docker.sock`. Segredos = env vars do stack, mascaradas pelo Portainer.
- **Imagem (D08/D47/D54)**: Alpine leve via GHCR; rebuild só quando supervisor/Dockerfile/CI mudam + gatilho manual (workflow_dispatch). Tags **imutáveis** `shell-vN`; deploy reponta o compose via `StackUpdate` (repull); rollback da casca = repontar para `N-1`.
- **Healthcheck (D53)**: `exec eon health` — subcomando lê o heartbeat do supervisor num arquivo de estado interno; zero superfície de rede; Docker, Portainer e sidecar leem nativamente.
- **Watchdog (D40/D52)**: sidecar `autoheal` no PRÓPRIO stack, label-scoped — reinicia o container eon se unhealthy. `docker.sock` montado **somente no sidecar**, read-only; o container eon nunca o enxerga. Tudo no compose — zero configuração no host.
- **Acompanhamento (D50)**: CI publica `shell-vN` → `StackUpdate` → **verificação fora-de-banda**: container up, health verde, tail de logs, eventos. Runbook obrigatório desde o M1 (`docs/runbooks/deploy-via-portainer.md`).
- **Chaos drills (D51)**: `StackStop/Start`, kill de container, observação de recuperação — executados pelas ferramentas Portainer, documentados como runbook (`docs/runbooks/continuity-drills.md`), rodados no M5.
- **Dashboard (D55)**: publicado em `0.0.0.0:8089→8080` — escolha deliberada do operador (homelab em rede de confiança); M5 re-visita a exposição como endurecimento **não-bloqueante**.

## Consequências

- "Nunca para" na camada-casca = docker `restart=unless-stopped` + healthcheck + supervisor + sidecar autoheal — quatro watchdogs em série, todos imunes ao autômato.
- O binário vivo melhora LOCALMENTE (artefatos vN, ADR-0004) — a imagem é só a casca, coerente com D11.
- Deploy e rollback são atos de Portainer com verificação fora-de-banda; o autômato nem sabe que existem.
