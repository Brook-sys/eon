# ADR-0001: Go único; binário estático único; três modos de processo

- **Status**: aceito (2026-10-13)
- **Origem**: D01, D07, D08, D42 — docs/plan/00-DECISIONS.md

## Contexto

A v1 acumulou múltiplos harnesses e binários; deploys com runtime aninhado são impossíveis em container leve; free-tier exige build rápido e reprodutível offline.

## Decisão

Uma linguagem (Go), um binário estático (`eon`, CGO off), três modos de processo: `eon supervisor` (PID 1), `eon core`, `eon worker`. Subcomandos de apoio: `health`, `sandbox`, `version`. Papéis de subprocesso (probes, worker-child) são re-exec do PRÓPRIO binário via env — zero segundos binários, zero plugins runtime. Go pinado por minor no `go.mod`; upgrade = Improvement deliberada (D42).

## Consequências

- Imagem final Alpine mínima (~30MB com git); sem runtime Docker aninhado; container é só casca (D08).
- `restart=unless-stopped` + healthcheck + supervisor cobrem a morte do container: "nunca para" é propriedade do SISTEMA.
- Testes rodam com CGO off por construção: binário de teste dinâmico é rejeitado pelo sandbox (o gate exige `CGO_ENABLED=0`).
