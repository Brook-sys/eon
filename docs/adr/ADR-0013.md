# ADR-0013: Missões e frentes — 3 frentes intercaladas; F1 estuda o domínio

- **Status**: aceito (2026-10-13)
- **Origem**: D13, D20, D21, D23, D43 — docs/plan/00-DECISIONS.md

## Contexto

Uma só missão mono-maníaca enferruja; multi-agência conversacional foi lição de deriva da v1. O trabalho tem que ser modular, intercalado e verificável — e a primeira missão tem que ser auto-referencial o bastante para nunca depender de contexto externo frágil.

## Decisão

- **Missões (D13)**: N missões lógicas, 1 executando por vez (serialidade D10). Missão é contrato de domínio com condição terminal explícita.
- **Frentes (D20)**: três desde o início, intercaladas pelo scheduler (ADR-0008): F1 (projeto/epistêmica), F2 (pensamentos/curadoria), F3 (self). Contrato uniforme `WorkFront`; adicionar frente = registrar implementação, zero mudança no kernel.
- **Primeira missão F1 (D21)**: estudar o próprio domínio — agentes contínuos, auto-melhoria, harnesses para modelos fracos → base de conhecimento citada exportada como markdown no repo (`docs/knowledge/`, formato D36). Auto-referencial, verificável; lista de leitura semente em docs/plan/04-SCIENCE.md.
- **Web (D23)**: local primeiro; fetch web + search API free-tier como capabilities **opcionais** com degradação graciosa. Sem infraestrutura externa obrigatória.
- **Publicação (D43)**: relatórios periódicos de operação (continuidade, promoções/rollbacks, calibração, custos) em `docs/knowledge/` — o estudo publica o experimento que ele mesmo é.

## Consequências

- O produto já demonstra a tese na primeira missão: conhecimento citado end-to-end com modelo fraco.
- `docs/knowledge/` é legível por humano e autômato, diffável no git, índice verificável.
- A lista de leitura semente inclui o paper "AI Parenting" (ID arXiv = tarefa de pesquisa F1, questão aberta A09 — o plano não depende dela).
