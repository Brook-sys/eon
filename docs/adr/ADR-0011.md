# ADR-0011: Sandbox cego puro-Go com degradação full→basic→none

- **Status**: aceito (2026-10-13)
- **Origem**: D09, D19 — docs/plan/00-DECISIONS.md

## Contexto

Exec externa é obrigatória (F3 valida código) mas o modelo de ameaça é **desastre próprio + injeção web** — não adversário com exploits de kernel. O caso-alvo de deploy (container Docker padrão, Alpine via GHCR) dá chroot e seccomp sem privilégio; o homelab dá userns. Go puro evita a dependência de libseccomp/cgo.

## Decisão

Sandbox em Go puro (stdlib, CGO off) com **3 níveis**:

- `full`: user+mount+net namespaces (netns isola a rede por construção) + chroot interno + seccomp. Onde userns não-privilegiado funciona.
- `basic`: **chroot** + **seccomp BPF bloqueando rede** (bloqueia `socket(AF_INET/AF_INET6)` com `ERRNO|EPERM`; AF_UNIX segue vivo) + rlimits (CPU/AS/fsize/nofile) + timeout/SIGKILL no pgroup. Garantido em qualquer container Docker padrão.
- `none`: exec recusado — fail-closed. F3-de-código fica pendente; o resto do autômato segue vivo.

Princípio do **sandbox cego**: sem rede, sem segredos (env do job VAZIO), filesystem scratch com só o binário do job (argv[0] remapeado para `/job`). Detecção por probes que PROVAM **o que cada nível realmente usa** (D09: nível nunca é assumido): o probe de `full` replica a cadeia inteira do worker-child dentro do userns (chroot → seccomp → saída de rede negada — o clone com namespaces sozinho é só telemetria); o de `basic` prova chroot direto + filtro seccomp real com discagem EPERM. Onde o probe reprova, o nível degrada com honestidade — e o runner do GitHub (clone ok, chroot no userns negado) cai em `none` fail-closed em vez de farsa de `full`. Binário de job tem que ser estático (PT_INTERP recusado). Toda job é auditável: comando, timeout, outputs e `result.json` por job.

## Consequências

- M0 implementou: detecção por re-exec do próprio binário, filtro BPF hand-rolled, worker-child com chroot→rlimits→seccomp→execve, recusas legítimas, testes provando rede bloqueada de verdade dentro do sandbox.
- NPROC fica fora no M0 (semântica per-uid em host compartilhado) — revisitado no M5.
- Deps vendorizadas fazem build/teste offline funcionarem no `basic` (D19); sem `full`, o repositório de trabalho vive no scratch via cópia.
